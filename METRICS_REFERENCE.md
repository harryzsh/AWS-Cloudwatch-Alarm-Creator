## Tag-Based Alarms

Deployed via `cloudformation-tag-based-alarms.yaml`. Uses CloudWatch Metrics Insights SQL with tag filtering.

**Total: 10 alarms**  
**Parameters (all required):** `--tag-key`, `--tag-value`, `--sns-topic`  
**Naming:** `{TagValue}-{Service}-{Metric}-{SEVERITY}`  
**Actions:** AlarmActions + OKActions (notified on trigger and recovery)

### EC2 Instances

**Alarms:** 6  
**Namespace:** `AWS/EC2`

| Metric | WARNING | CRITICAL | Operator | Description |
|--------|---------|----------|----------|-------------|
| CPUUtilization | >90% | >98% | > | EC2实例CPU使用率 |
| StatusCheckFailed_System | — | ≥1 | >= | EC2系统状态检查失败 - AWS基础设施问题 |
| StatusCheckFailed_Instance | — | ≥1 | >= | EC2实例状态检查失败 - 实例配置问题 |
| InstanceEBSThroughputExceededCheck | ≥1 | — | >= | EC2实例EBS吞吐量超过实例最大限制 (Nitro only) |
| InstanceEBSIOPSExceededCheck | ≥1 | — | >= | EC2实例EBS IOPS超过实例最大限制 (Nitro only) |

### NAT Gateway

**Alarms:** 2  
**Namespace:** `AWS/NATGateway`

| Metric | WARNING | CRITICAL | Operator | Description |
|--------|---------|----------|----------|-------------|
| ErrorPortAllocation | >100 | — | > | NAT网关端口分配错误次数 |
| PacketsDropCount | >100 | — | > | NAT网关连接失败丢包数量 |

### VPN

**Alarms:** 2  
**Namespace:** `AWS/VPN`

| Metric | Dimensions | WARNING | CRITICAL | Operator | Description |
|--------|------------|---------|----------|----------|-------------|
| TunnelState (connection) | VpnId | — | <1 | < | VPN连接隧道状态异常 - 连接级别 |
| TunnelState (tunnel) | VpnId, TunnelIpAddress | — | <1 | < | VPN隧道状态异常 - 隧道级别 |

## Resource-Based Alarms

Configured in `alarm-config-resource-based.yaml`, generated by `resource_alarm_builder.py`. Creates dedicated alarms per discovered resource using stable hash-based CloudFormation logical IDs.

**Naming:** `{TagValue}-{Service}-{ResourceId}-{Metric}-{SEVERITY}`  
**Actions:** AlarmActions + OKActions (notified on trigger and recovery)  
**Dual severity:** metrics with both `threshold_warning` and `threshold_critical` generate two alarms each.

### EC2 (CWAgent)

**Alarms per instance:** up to 4 (2 metrics × 2 severities)  
**Namespace:** `CWAgent`  
**Primary Dimension:** InstanceId  
**Discovery:** Tagged EC2 instances, filtered to only those with active CWAgent data  
**Note:** Requires [CloudWatch Agent](https://docs.aws.amazon.com/AmazonCloudWatch/latest/monitoring/Install-CloudWatch-Agent.html) installed. Instances without CWAgent are automatically skipped.

| Metric | WARNING | CRITICAL | Operator | Description |
|--------|---------|----------|----------|-------------|
| mem_used_percent | >85% | >95% | > | EC2实例内存使用率 |
| disk_used_percent | >85% | >95% | > | EC2实例磁盘使用率 |

### MSK (Kafka)

## Severity Levels

| Severity | Suffix | Meaning |
|----------|--------|---------|
| WARNING | `-WARNING` | 预警阈值 — 需要关注，可能需要介入 |
| CRITICAL | `-CRITICAL` | 严重阈值 — 需要立即处理 |

**Important:** When changing an `AlarmName` in the template, CloudFormation cannot rename a physical resource in-place — it creates the new name first, then deletes the old. If the new and old names are identical or conflict, a rollback occurs. Always ensure the new `AlarmName` is genuinely different from the old one.
